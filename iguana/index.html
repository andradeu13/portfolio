Iguana Panel Dashboard Design System 2026

One panel for
the whole business.

An admin dashboard for service businesses in Ecuador: appointments, clients, money and an AI assistant in a single place, designed mobile-first and built on its own small design system.

ProductAdmin panel
StackHTML · CSS · JS
LanguageSpanish (EC)
Views6 + dialogs

Context

Run the day, not the software

Owners of small service businesses (salons, barbers, studios) juggle their agenda, who has paid, what they spent and the messages from clients, often between appointments and from a phone. Iguana Panel brings those four jobs into one interface: Appointments, Clients, Money and an AI Assistant that answers clients on WhatsApp.

Inicio

What matters today

Next appointment with a countdown, money collected and spent today, what is still owed, and the month versus the previous one.

Calendario

Daily timeline first

Week strip plus a day timeline as the main view. The month view is one tap away. On mobile you swipe between days.

Dinero

Income, expenses, profit

Summary, income and expense views, with every change versus the previous period shown as an arrow and a label.

Clientes

Directory and history

Search, client history and quick actions to message them.

Asistente

AI assistant setup

Configure the assistant that replies on WhatsApp, with a floating shortcut to open the chat.

Ajustes

Services, hours, rules

Services, opening hours and booking rules in one place. Invoicing is marked "Soon".

Design decisions

Decisions you can see in the product

Each decision below is visible in the interface and in the code, so you can check it in the demo.

Hierarchy

Daily calendar as the main view

The day is the unit of work, so the timeline leads and the current or next appointment is highlighted. The upcoming-appointment banner was later made shorter to leave more room for the day.

Clarity

Never color alone

Every change versus the previous period is an arrow plus text ("9% more", "34% less"), so meaning does not depend on green or red.

Mobile

Sidebar becomes a tab bar

On phones the left navigation turns into a bottom bar with the main views and a "More" dialog, respecting safe areas on notched devices.

Navigation

Every view has its own address

Routes like #/inicio or #/dinero/resumen keep the back button and direct links working.

Accessibility

Keyboard and screen readers

Skip link, labelled landmarks, native dialog elements and a tab order that follows the visual order.

Prototyping

Design mode with sample data

A small demo API replaces the backend so the whole interface can be reviewed by opening one file, with special views for sign-in and admin.

Design system

A small system, defined in tokens

The whole interface is built from a short list of tokens declared once in styles.css: color, shape, a 4/8 spacing scale, two typefaces, layers and layout measures. Components only consume tokens, so a change in one place changes the whole panel.

Typography

Plus Jakarta Sans + JetBrains Mono

Plus Jakarta Sans (400–800) for interface and numbers; JetBrains Mono for times, dates and small labels, which makes schedules scan faster.

Shape & space

Radii 14 · 20 · 28 · pill

Spacing steps 4 · 8 · 12 · 16 · 24 · 32 · 48 px. One icon set with a single 1.75 stroke for the whole panel.

  • Color is never the only signal. Status and change always carry text or an arrow.
  • Semantic colors are reserved. Green = income and success, orange = expense, red = danger. They are not used for decoration.
  • Touch first. Primary controls stay at least 44 px tall on mobile and layouts adapt at tablet, phone and 320–380 px widths.
  • One source of truth. Tokens first, then components, then views.
